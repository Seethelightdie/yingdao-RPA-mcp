# Domain Docs

工程技能在探索本仓库时应如何消费域文档。

## 探索前先读

- 仓库根的 **`CONTEXT.md`**（若存在），或
- 根的 **`CONTEXT-MAP.md`**（若存在）——它指向每个上下文各自的 `CONTEXT.md`
- **`docs/adr/`** —— 读与你即将改动的区域相关的 ADR

若这些文件尚不存在，**静默继续**：不要提示缺失、不要主动建议创建。
`/domain-modeling` 技能（经 `/grill-with-docs` 触达）会在术语或决策真正敲定时惰性创建它们。

## 文件结构

单上下文仓库（绝大多数仓库）：

```
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-xxx.md
│   └── 0002-xxx.md
└── src/
```

## 使用词汇表的术语

当你的产出需要命名一个域概念（issue 标题、重构提案、假设、测试名）时，
使用 `CONTEXT.md` 定义的术语。不要漂移到词汇表明确回避的同义词。

如果你需要的概念还不在词汇表里，这是一个信号——要么你在发明项目不用的语言（请三思），
要么存在真实缺口（记下来交给 `/domain-modeling`）。

## 冲突 ADR 要显式标记

如果你的产出与既有 ADR 矛盾，显式指出而不是悄悄覆盖：

> _与 ADR-0007 矛盾——但值得重开讨论，因为……_
